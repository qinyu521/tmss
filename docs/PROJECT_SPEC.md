# 项目规格 · 天命史书

## 1. 目标

在浏览器中提供可玩的架空历史大地图策略原型：真实可交互的 3D 地图、高信息密度界面、确定性规则结算、三国差异化国情、原创人物与兵种视觉、可存档与可追溯事件。首版聚焦单机纵向流程，不包含多人联机、实时战术战斗与本地大模型。

## 2. 纵向流程

1. 开始页选择势力（匈奴 / 大雍 / 大楚）与身份（君主 / 州牧 / 将军 / 军师）。
2. 进入 3D 地图：州府、道路、山川、城池/关隘/港口/资源点、势力边界、部队旗标。
3. 查看州府、军队、人物、原型、世家/军阀、兵种、情报。
4. 下达命令：行军、整军、侦察、征募、征粮、加税、贸易、赏赐部落、平衡皇子、协商世家、任命。
5. 后端校验权限/资源/道路/时序 → 结束本旬（7 天）→ NPC 同步行动 → 资源与政治结算 → 行军/战斗/占领。
6. 事件日志 + 史官编年 → 自动存档 → 可手动存档/读档/重开时间线。

## 3. 架构

```text
apps/web (React/Vite/Three.js)
   │  /api  (fetch, Vite proxy)
   ▼
apps/api (Fastify, node:sqlite WAL)
   │  imports
   ▼
packages/shared
   ├─ types.ts           DTO / 种子类型 / 游戏状态 / 命令 / 事件
   ├─ constants.ts       势力视觉 Token、身份权限矩阵、日期/格式
   ├─ balance.ts         资源、军需、战斗、政治、初始库存
   ├─ unitProfiles.ts    22 兵种派生数值与视觉档
   ├─ dataset.ts         种子索引、州府经济推导、初始部署、连通
   ├─ engine/            state / orders / movement / battle / economy /
   │                     politics / npc / turn / chronicle / view
   └─ engine.test.ts     17 条规则测试
```

存档：`games(state_json)` + `game_events` + `chronicle_entries` + `saves`。参考数据由种子同步为可查询镜像。

## 4. 关键设计决策

- **确定性**：一回合 = 7 天；所有随机使用 mulberry32 + 固定种子；战报保存种子可重放。
- **信息不对称**：`buildPlayerView` 不向客户端下发敌方精确库存/兵力/士气；情报有来源与可靠度。
- **权限硬校验**：服务端 `validateOrder` 是唯一可信校验；前端只做提示。
- **原创资产**：336 SVG 肖像、22 兵种图标与低多边形模型全部程序生成；不使用商业素材。
- **派生数据透明**：州府经济、军区驻地、兵种数值、地图美术均为派生并在数据字典记录依据；原始 JSON 未改。
- **不伪造模拟**：UI 的数字全部来自 `GameState`；没有静态假数据。

## 6. 验收对照

1. README 命令可启动前后端 —— 见 README「快速开始」。
2. 选三国之一进入 3D 地图、颜色区分、拖动/缩放/旋转倾斜 —— MapScene + MapView。
3. 336 人物、原型备注、职位、世家/军阀关系；姓名多样 —— 人物面板与种子校验。
4. 兵力精确 40/80/30 万；18 条分配合计一致 —— 校验脚本 + 测试。
5. 三国国情机制真实影响结算 —— `engine/politics.ts` / `economy.ts` + 测试。
6. 22 兵种完整、数据差异、资源/地形/补给/训练/上限 —— `unitProfiles.ts` + 兵种面板。
7. 至少一项政治与一项军事命令经后端校验结算，日期 +7 天，产生事件；错误命令有原因 —— API 集成测试。
8. 存档/读档、刷新恢复 —— SavePanel + API 测试 + Playwright 冒烟。
9. 规则事件可查，史官摘要不改事实 —— EventsPanel；`facts` 直接来自事件。
10. 种子校验、单测、前端构建、类型检查真实执行 —— IMPLEMENTATION_STATUS。
11. Docker Compose 可部署低配 VPS；前端可独立部署；无 LLM 密钥可玩 —— DEPLOYMENT + 默认模板。
12. README 明确 1 核 2G 定位 —— 已写明。
