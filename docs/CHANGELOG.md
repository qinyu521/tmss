# 变更记录

## 0.6.1 · 2026-10-28（人物原型归属审计修复分支）

### 修复

- 原型校验器不再把过时的硬编码例外（例如把晋代原型一律要求归大楚、把明代朱元璋要求归大楚）误报为冲突。
- 校验规则改为读取权威种子 `historical_archetypes.primary_faction_key`，并单独核验用户指定的核心原型归属。
- 对 `COMMON` 中立候选原型，新增岗位限制：只可用于在野人才、州府地方官、世家、门客、地方军阀等岗位，避免中立原型被放进国家核心君主/中枢岗位。
- 将明确归属方向写成回归测试，覆盖李靖、诸葛亮、赵奢、曹操、司马懿、祖逖、房玄龄、杜如晦、赵普、包拯、朱元璋、韩信、周瑜、鲁肃、陆逊、孟珙、左宗棠、木华黎、速不台、耶律阿保机、耶律楚材、拓跋珪、完颜宗弼、伯颜、脱脱，以及中立候选池代表人物。
- 修订 `AGENTS.md` 数据保护规则：不允许静默修改；但对用户确认的错误，允许通过独立分支、可审查 diff、变更日志和回归测试进行修正。
- 更新种子校验报告，注明原先报告中的 12 条冲突是旧规则造成的误报，并注明本分支完整运行结果需由本地/CI 实测确认。

### 验证状态

- 已对权威种子进行静态审计：100 个历史原型、336 个原创人物；历史原型主归属字段与角色映射未发现冲突；118 个中立候选原型角色全部落在在野/地方官/世家相关岗位。
- **本修改环境尚未执行 Node/Vitest 测试**。合并前必须由 GitHub Actions 或本地实际运行 `npm run validate:seed`、`npm test`、`npm run typecheck` 和 `npm run build`，以真实运行结果为准。

## 0.6.0 · 2026-10-28

### 新增

- 人物生命周期（B2，`engine/lifecycle.ts`，schema v2）：每旬按年龄段确定性掷骰（青年 0.1% / 壮年 0.2% / 中年 0.5% / 老成 1.5%，参战主将 +1.5% 战死），随机种子 `mulberry32(hash("{seed}-life-{turn}"))` 可重放；死因分病逝/寿终/战死/暴卒，每次死亡生成 succession 事件（前后状态与证据俱全）。
- 权力继承：州府主官（副手优先、否则同势力在世未主政者治理最高）、部队主将（军区副将优先，士气 -8）、匈奴部落首领（heir 接任，忠诚 -12）、大楚世家家主（heir 接任，支持 -6）、大雍皇子（退出派系、影响力重排、朝局 -10）；玩家人物身故后身份由活人承继，不进入死人视角。
- 成长：potential ≥ 70 且在世者每年（每 52 旬）主属性 +1（上限 95），只写 growthNote/attrs，不发事件。
- 存档迁移框架：`migrateState` 按 `MIGRATIONS` 版本链执行，旧存档字段补齐后继续运行。

### 验证

- `npm run typecheck` 通过（shared / api / web）。
- `npm test`：6 个测试文件，64/64 通过。
- `npm run validate:seed`：硬性错误 0；警告 3；旧校验规则原型冲突 12（该分支已修订审计规则）。
- `npm run build` 通过。上述为 0.6.0 原开发记录，不能替代 0.6.1 分支的重新运行结果。
